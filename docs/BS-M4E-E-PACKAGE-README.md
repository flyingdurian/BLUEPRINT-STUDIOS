# BLUEPRINT STUDIOS — M4E-E Production Integration & QC Handoff

**Purpose:** Normative design specification plus a **reference executable QC baseline**, not a finished Godot release or a claim of owner visual acceptance.

The package is a *changed-file-only* proposal for `flyingdurian/BLUEPRINT-STUDIOS`. It was designed against the inspected `feature/bs-m4e-production-rig` branch, while Cursor continues the M4E-C/D implementation. Nothing has been committed or pushed.

## Current repository compatibility

The live branch's M4-C compiler still writes v1 previs manifest with `productionLocked: false` and `execute: false`; its M4-D assembler creates `pilot-final.mp4` before QC. Cursor must implement the v2 compiler, executable action bindings, Godot evidence and candidate-first assembly before production QC can report success. The supplied harness **intentionally fails closed** against the old previs artifacts.

## Run the reference tests

From repository root after extracting the files:

```bash
python -m unittest discover -s tests -p 'test_m4e_e_qc.py' -v
```

The harness needs `ffprobe`, `ffmpeg`, and `numpy` (`pip install numpy`) for its full run. In addition to existing M4-D outputs, M4E-E expects engine preflight and exact per-frame telemetry generated by the new Godot production runner.

```bash
python tools/qc_production_render.py \
  --job-dir data/renders/jobs/<job-id> \
  --stage-plan docs/examples/BS-M4-PILOT-STAGE-PLAN.json \
  --rig-contract docs/examples/BS-M4E-RIG-CONTRACT.json \
  --face-contract docs/examples/BS-M4E-FACIAL-RIG.json \
  --actions-contract docs/examples/BS-M4E-ACTION-BINDINGS.json
```

Exit 0 indicates **automated technical baseline passed only**; human review and additional golden-frame gates are still needed for final promotion. Exit 2 = QC blockers, exit 3 = invalid/unavailable evidence or tools. `qc_report.json` is always written. The script NEVER promotes a candidate or changes an approved final file.
